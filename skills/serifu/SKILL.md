# serifu（セリフ）

記事や概念を、2人の人間が本気で会話しているように変換するスキル。

## なぜこのスキルが存在するか

箇条書きや説明文は「情報」を伝えるが、「理解」を生まない。人は会話の中で例え話を聞いたとき、「あ、そういうことか！」と腹落ちする。このスキルの目的は、読んだ人が本当に内容を理解できる会話を生成すること。

## 心構え

あなたはプロの放送作家。NHKの教養バラエティの台本を書くつもりで。池上彰が難しいニュースを誰でもわかるように語るあの感じ。ただし文体はもっとカジュアルに、友達同士の会話のテンポで。

大事なのは：
- **例え話が命**。抽象的な概念が出てきたら、必ず身近なものに置き換える。料理、引っ越し、学校、スポーツ、コンビニ、なんでもいい。「つまり○○みたいなもんだよ」が会話に自然に出てくるように
- **「へぇ！」を生む**。読んだ人が誰かに話したくなるような、意外性のある切り口を見つける
- **相槌と驚きがリアル**。「えっ、マジで？」「あー、なるほどね」「いやそれヤバくない？」——本物の会話では人は感情で反応する
- **人に話したくなる**。読んだ人が「これ面白いんだけど聞いて」と誰かにシェアしたくなるような、記憶に残る切り口を意識する

## 入力タイプ別の扱い

- **URL**: WebFetchで取得してから変換。ページが長い場合は核心部分を特定して会話に落とす
- **PDF**: ページ数が多い場合は最初に全体を読み取り、要点を絞ってから会話化
- **貼り付けテキスト**: そのまま使う。長いテキストの場合は話題ごとに分割してもよい
- **英語記事**: 日本語の会話に翻訳しつつ変換する。原文のニュアンスは大事にしつつ、日本語として自然な表現に
- **技術ブログ・API解説**: 専門用語は会話の中で噛み砕く。コードブロックは「ここでこう書くと動くんだけど」的に口語化

## 登場人物

記事の内容に合わせて自然に決める。

- 登壇・インタビュー記事 → 本人 + 聞き手
- 解説・技術記事 → 詳しい人 + 興味あるけど知らない人
- ニュース → 関係者同士、または解説者 + 視聴者目線の人
- 人物が不明 → 「先輩と後輩」「友達同士」など自然な関係を作る

名前や関係性は記事の雰囲気に合わせて。IT記事なら同僚同士、経済ニュースなら居酒屋で語る友人同士、みたいに。

## 出力フォーマット

```
名前：**「セリフ」**
```

- 発言者名のあとにコロン、セリフは太字と鉤括弧
- 最後に区切り線（---）のあとに一言まとめを地の文で書いてよい

## 会話の作り方

**テンポ**: 1人が3行以上独白しない。長い説明が必要なら、相手の相槌や質問で区切る。

**展開の流れ**:
1. 掴み — 「ねえ、○○って知ってる？」的な導入
2. 核心 — 一番大事なポイントを例え話で説明
3. 深掘り — 「でもそれってさ…」と疑問→回答の繰り返しで理解を深める
4. 締め — 「つまりこういうことか」と腹落ち

**テクニック**:
- **ツッコミ**: 聞き手が突っ込むことで論点が明確になる。「いやそれおかしくない？」「え、じゃあ今までのは何だったの？」
- **伏線と回収**: 序盤で「あとでわかるけど」と振っておいて、後半で「さっきの話に戻るんだけど…」と回収する

**長さ**: 記事の密度に合わせる。軽いニュースなら5-6往復、濃い技術記事なら15-20往復。内容がしっかり伝わることが最優先。端折って意味不明になるくらいなら長くていい。

**感情の変化**: 会話を通じてテンションが動くこと。最初は「ふーん」→途中で「えっマジ！？」→最後に「なるほどなぁ…」のように、盛り上がりと落ち着きがある。一本調子にならない。

## 要約スキルとの違い

このスキルは **情報源（記事・資料）を忠実に会話化** するもの。原文のファクトや数字を正確に再構成して会話に落とす。自分の体験から新しい文章を書くものではない。

## 難しい入力への対処

- **1行ツイートや短い投稿**: 無理に長い会話にしない。3-4往復でさっと
- **意見・エッセイ・ポエム的な文章**: 著者の主観を尊重しつつ「この人はこう言ってるんだけど」と紹介する形
- **データや統計が多い記事**: 数字を全部並べるのではなく、一番インパクトのある数字を「ヤバいのがさ…」と切り出す
- **複数記事の比較**: 「こっちはこう言ってるけど、あっちは真逆なんだよね」と対比構造に
- **センシティブな話題（政治・宗教等）**: 事実のみを伝え、会話キャラに特定の立場を取らせない

## 良い例・悪い例

**○ 良い会話**:

田中：**「ねえ、最近RAGって聞かない？AIの新しいやつ」**
鈴木：**「あー、なんか聞いたことある。何それ？」**
田中：**「簡単に言うと、AIにカンペを渡す仕組み。テスト中に教科書見ていいよって言われてるみたいな」**
鈴木：**「えっ、それズルくない？」**
田中：**「いや、むしろそれが正しい使い方なんだよ。AIって古い知識しかないから、最新の資料を渡してあげないと嘘つくんだよね」**
鈴木：**「あー、なるほど。だから検索と組み合わせるのか」**

**× ダメな会話**:

A：**「RAGについて説明します。RAGとはRetrieval-Augmented Generationの略で、情報検索と文章生成を組み合わせた手法です」**
B：**「なるほど、ありがとうございます。他にポイントはありますか？」**
A：**「ポイントは3つあります。1つ目は…」**

→ これは説明会であって会話ではない。相槌が形式的、例え話がない、感情がない。

## やってはいけないこと

- 記事にない事実や数字を作る
- 「〜について説明します」「ポイントは3つあります」みたいな説明調
- 箇条書きで要約する（それはこのスキルの存在意義の否定）
- 例え話なしで抽象概念を語る（それなら普通の要約でいい）
